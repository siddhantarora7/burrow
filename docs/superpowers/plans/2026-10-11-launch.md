# burrow launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the user chose inline execution, 2026-10-11). Steps use checkbox (`- [ ]`) syntax for tracking. Compact by the user's request: each task names exact interfaces and the tests that pin them; write the failing test first, then the code, run, commit.

**Goal:** Turn the one-pet status display into a shared garden that tells you, and your friends, when your agent is waiting on you; then put it on the internet.

**Architecture:** Pure logic lands in `packages/core` (wait ledger, link parsing, poke guard) and `apps/web/lib` (alert transitions, reducer), each unit-tested. The Worker grows three HTTP routes and a socket handshake; PetDO owns tokens, claims and the ledger; BurrowDO owns membership, pokes and broadcast. The web page signs in from a URL fragment and keeps a web token in localStorage.

**Tech Stack:** TypeScript 6, vitest, Cloudflare Workers + Durable Objects (hibernating WebSockets), Next.js 16 App Router, Web Audio + Notification API. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-11-burrow-launch-design.md`

## Global Constraints

- No new runtime or dev dependencies. The CLI stays zero-dependency.
- Hooks still send exactly `{v, type, at, session}`; nothing in this plan widens the wire event.
- Web tokens can hello and poke only; they never authorise `POST /v1/events`.
- Claim: one use, 10 minutes, at most 5 open per pet; web tokens at most 10 per pet; redeem limited to 10/min per pet.
- Pokes: target must derive `wave` now; one poke per sender per target per 60 s.
- `MAX_MEMBERS` = 24 (409 when full).
- Lowercase voice in all UI and CLI copy ("Claude Code" keeps its case).
- Commits carry no co-author or "Generated with" lines. Use npm 12 if installing.
- Keep test pets and tooling in `.superpowers/`.

## Review Focus

1. A claim link opened twice (refresh, or pasted to a friend): the second open must not sign anyone in and must leave the page usable as a plain viewer. → Task 3 test "redeem twice".
2. A stored web token that the server no longer knows (DO reset, pruned to 10): the page must forget it on `welcome {me: null}`, not keep showing signed-in UI. → Task 5 reducer test.
3. Page loaded while your pet is already waving: no alert burst on load, only on later transitions. → Task 6 test "first observation".
4. A link with trailing slash, query or fragment, or uppercase id: `join` must still find the burrow; garbage must fail with a clear message. → Task 1 parseBurrowLink tests.
5. Poke spam and self-poke: repeated presses within 60 s, poking yourself, poking a non-waving pet: all silently dropped. → Task 1 canPoke tests.
6. A reloaded second-screen tab nobody has clicked: the chime is locked by the browser; the chip must say `click for sound` instead of failing silently. → Task 6 alertChip test.

### Task 1: core: wait ledger, link parsing, poke guard, protocol

**Files:** Create `packages/core/src/waits.ts`, `packages/core/src/links.ts`, `packages/core/src/poke.ts`; modify `packages/core/src/protocol.ts`, `packages/core/src/index.ts`. Tests: `packages/core/test/waits.test.ts`, `links.test.ts`, `poke.test.ts`.

**Produces:**
- `interface WaitLedger { day: string; waitedMs: number; open: Record<string, number> }`
- `emptyLedger(day: string): WaitLedger`
- `foldWait(l: WaitLedger, ev: Ev, day: string): WaitLedger` (pure; returns a new object)
- `interface Today { day: string; waitedMs: number; meals: number }`
- `parseBurrowLink(input: string): string | null` (burrow id or null)
- `CLAIM_TTL_MS = 600_000`, `POKE_GAP_MS = 60_000`
- `canPoke(a: { from: string | null; to: string; members: Member[]; now: number; lastPokeAt: number | undefined }): boolean`
- protocol: `Member.today?: Today`; `ServerMsg` adds `{t:'event'; …; today?: Today}`, `{t:'welcome'; me: string | null}`, `{t:'poke'; from: string; to: string; serverNow: number}`; `ClientMsg = {t:'hello'; token?: string} | {t:'poke'; to: string}`.

- [ ] Tests for `foldWait`: needs_input then prompt adds the gap; error opens too; a second needs_input while open keeps the first start; the cap is `TIMING.waitMaxMs`; another session's event does not close it; two parallel sessions add both; a new day resets `waitedMs` but keeps open waits; opens older than the cap are closed at the cap on the next fold; an event whose `t` is before the open start adds 0, never negative.
- [ ] Tests for `parseBurrowLink`: `https://x.vercel.app/b/abcdefgh12` → id; with trailing `/`, `?h=3`, `#claim=…`; uppercase id lowercased; bare id; `http://localhost:3000/b/abcdefgh12`; rejects `''`, `/b/short`, `https://x/p/abcdefgh12`, ids with `i l o u`.
- [ ] Tests for `canPoke`: true for a signed-in member poking a waving member; false when `from` null, not a member, equal to `to`, target not a member, target not waving, last poke under 60 s ago; true again at exactly 60 s.
- [ ] Implement, run `npx vitest run packages/core`, commit `core: wait ledger, burrow links, poke guard`.

### Task 2: server: joining, hatch into a burrow, wait ledger forwarding

**Files:** Modify `apps/server/src/index.ts`, `pet.ts`, `burrow.ts`, `logic.ts`; test `apps/server/test/logic.test.ts`.

**Consumes:** `foldWait`, `emptyLedger`, `Today`, `MAX_MEMBERS`, `parseToken`.
**Produces:**
- `validateHatch` accepts optional `burrowId` (must satisfy `isId`) → `Hatch.burrowId?: string`.
- `PetDO.auth(secret): Promise<MemberProfile | null>` (CLI token check), `PetDO.event` folds the ledger (`ledger` key) and passes `today` to `BurrowDO.ingest(petId, ev, today)`.
- `BurrowDO.join(profile, now): Promise<'ok' | 'not_found' | 'full'>` (idempotent `ok` for an existing member); `BurrowDO.exists(): Promise<boolean>`.
- Routes: `POST /v1/pets` with `burrowId` → join instead of create (404 `burrow not found`, 409 `burrow is full`, checked before hatching so nothing is orphaned); `POST /v1/burrows/:id/join` with Bearer token → `{burrowId, name}`.
- [ ] Tests: `validateHatch` accepts a valid `burrowId`, rejects `'nope'`; ingest/today shape covered by smoke.
- [ ] Implement; `npm run typecheck`; commit `server: join burrows, hatch into a friend's burrow, forward waited-today`.

### Task 3: server: claims, web tokens, socket hello and pokes

**Files:** Modify `apps/server/src/index.ts`, `pet.ts`, `burrow.ts`, `logic.ts`; test `apps/server/test/logic.test.ts`.

**Consumes:** `CLAIM_TTL_MS`, `canPoke`, `POKE_GAP_MS`, `derive`.
**Produces:**
- `logic.ts`: `parseClaim(s: unknown): { petId: string; code: string } | null` (code 16 Crockford chars), `pruneClaims(claims: Claim[], now): Claim[]` with `Claim = { hash: string; exp: number }` (drops expired, keeps newest 5), `capList<T>(xs: T[], n): T[]` (keeps newest n).
- `PetDO.newClaim(now): Promise<string>` (returns `petId.code`), `PetDO.redeem(code, now): Promise<{ token: string } | null>` (one use; mints web token), `PetDO.checkWeb(secret): Promise<boolean>`.
- Routes: hatch response gains `claim`; `POST /v1/claims` (Bearer CLI token) → `{claim}`; `POST /v1/claim {claim}` → `{petId, token}` or 400/401, CORS enabled.
- BurrowDO `webSocketMessage`: `hello` → verify with `PET.checkWeb`, `serializeAttachment({me})`, reply `welcome`; `poke` → `canPoke` with `lastPokeAt` from the attachment's `pokes` map, then broadcast `poke` and record the time.
- [ ] Tests: `parseClaim` accepts `abcdefgh12.0123456789abcdef`, rejects wrong lengths and missing dot; `pruneClaims` drops expired and caps at 5; redeem-twice is covered by smoke (second redeem → 401).
- [ ] Implement; typecheck; commit `server: one-time claim links, web tokens, socket hello and pokes`.
