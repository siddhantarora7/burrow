# Stats, the status line and a way home: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** per-day and per-week stats from events for every pet, opt-in tokens and cost, shown in a Claude Code status line, a `stats` terminal table and a garden panel; plus a "my garden" link home.

**Architecture:** a pure `foldStats` in core keeps a 7-day book per pet, folded in PetDO next to the wait ledger and sent to gardens with `today` and `week`. The CLI gains two local-only readers (transcript tokens, status-line cost) that attach a `usage` delta to stop events when sharing is on, a status-line script bundled like the hook, and a table renderer over a new public snapshot endpoint.

**Tech Stack:** TypeScript, Cloudflare Workers + Durable Objects, Next.js 16, esbuild, vitest.

**Spec:** `docs/superpowers/specs/2026-10-13-burrow-stats-design.md`

## Global Constraints

- Default wire format unchanged: `{v, type, at, session}`. The only addition is `usage: { tokens?, cost? }`, allowed on `stop` and `session_end` only, `tokens` an integer 0..50_000_000, `cost` a finite number 0..500. Any other key is still rejected.
- Usage is opt-in (`init` asks, default no; `usage on|off`). Nothing from the transcript leaves the machine except the token sum. Cost only from Claude Code's `cost.total_cost_usd`; no price table.
- Koban, caps and ranks unchanged. Stats sort by tasks, then active time.
- Status line never blocks on the network and never throws; exits 0 with whatever it can print.
- Deploy order: server, then web, then CLI 0.3.0.
- No new dependencies. npm 12. No Claude attribution in commits. Lowercase UI copy.

## Review Focus

1. CLI 0.3.0 posting `usage` to a server that predates it gets 400 and the event is lost. Expected: the hook resends once without `usage`. (Test in Task 3.)
2. Turning sharing on mid-session with a 200 MB transcript. Expected: the first read starts at the end of files over 20 MB, so the hook stays fast; smaller files count from the start. (Task 3.)
3. Malformed or empty status-line stdin, no `~/.burrow`, offline API. Expected: prints a line or nothing, exit 0. (Task 4.)
4. A day rollover and a week window: an event after local midnight starts a new day; days older than 6 days before today drop out of `week`. (Task 1.)
5. A wrapped status-line command that hangs. Expected: killed after 1.5 s, burrow's line still prints. (Task 4.)

```ts
// stats.ts
import { TIMING } from './derive'
import type { Ev, WireUsage } from './events'
import { GROW } from './grow'
import type { WaitLedger } from './waits'

const OPENS = new Set(['needs_input', 'error'])
const HOUR = 3_600_000
const DAY = 86_400_000

export const emptyDay = (day: string): DayStats => ({ day, waitedMs: 0, meals: 0, turns: 0, tasks: 0, activeMs: 0, replies: 0, replyMs: 0, hourMs: Array<number>(24).fill(0) })
export const emptyBook = (): StatsBook => ({ days: [], seen: {} })
const dayNum = (d: string) => Date.UTC(+d.slice(0, 4), +d.slice(5, 7) - 1, +d.slice(8, 10)) / DAY

export function foldStats(b: StatsBook, ev: Ev, c: FoldCtx): StatsBook {
  const last = b.days.at(-1)
  const today: DayStats = last?.day === c.day ? { ...last, hourMs: [...last.hourMs] } : emptyDay(c.day)
  const before = b.seen[ev.session]
  const waiting = c.prev.open[ev.session] !== undefined
  if (before !== undefined && !waiting) {
    const gap = ev.t - before
    if (gap > 0 && gap <= TIMING.quietMs) { today.activeMs += gap; today.hourMs[c.hour]! += gap }
  }
  if (ev.type === 'prompt') today.turns++
  if (ev.type === 'stop' && c.runMs >= GROW.minRunMs) today.tasks++
  const opened = c.prev.open[ev.session]
  if (opened !== undefined && !OPENS.has(ev.type) && ev.type !== 'session_end') {
    today.replies++
    today.replyMs += Math.min(TIMING.waitMaxMs, Math.max(0, ev.t - opened))
  }
  if (c.usage?.tokens) today.tokens = (today.tokens ?? 0) + c.usage.tokens
  if (c.usage?.cost) today.costUsd = (today.costUsd ?? 0) + c.usage.cost
  today.waitedMs = c.waitedMs
  today.meals = c.meals
  const seen: Record<string, number> = {}
  for (const [s, t] of Object.entries(b.seen)) if (ev.t - t < HOUR) seen[s] = t
  if (ev.type === 'session_end') delete seen[ev.session]
  else seen[ev.session] = ev.t
  const days = [...b.days.filter((d) => d.day !== c.day && dayNum(c.day) - dayNum(d.day) < 7), today]
  return { days, seen }
}

export function sumWeek(days: DayStats[], day: string): DayStats {
  const w = emptyDay(day)
  for (const d of days) {
    if (dayNum(day) - dayNum(d.day) >= 7 || dayNum(d.day) > dayNum(day)) continue
    for (const k of ['waitedMs', 'meals', 'turns', 'tasks', 'activeMs', 'replies', 'replyMs'] as const) w[k] += d[k]
    d.hourMs.forEach((ms, h) => (w.hourMs[h]! += ms))
    if (d.tokens !== undefined) w.tokens = (w.tokens ?? 0) + d.tokens
    if (d.costUsd !== undefined) w.costUsd = (w.costUsd ?? 0) + d.costUsd
  }
  return w
}
```

  In `events.ts`: `WIRE_KEYS` gains `'usage'`; after the session check, if `'usage' in b`: require `b.type` to be `stop` or `session_end`, an object whose keys are a subset of `tokens`, `cost`, `tokens` a safe integer 0..50_000_000, `cost` finite 0..500; copy it onto the value. `protocol.ts`: `Member.week?: DayStats`; the `event` message gains `week?: DayStats`.
